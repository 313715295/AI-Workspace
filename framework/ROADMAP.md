# AI Workspace Framework 路线图

本页导航当前源码能力与后续方向，不保存实施任务或消费者采用记录。版本生命周期取 VERSION.json 与 RELEASE_MANIFEST.json；项目自行决定和记录采用。Framework 的演进以保障交付质量、降低沟通、执行、验证和返工总成本为依据。

## 当前 2.0 源码候选

2.0.0 仍为开发候选，详见[版本说明](versions/2.0.0/README.md)与[发行清单](versions/2.0.0/RELEASE_MANIFEST.json)。已形成的源码包括责任转换与恢复、有类型证据、四维意图分类、完整有效规则集合与依赖快照、本地/Git/HTTPS 来源读取，以及显式范围内的知识查询。当前 Tool Contract4 / navigation3 由项目 AGENTS 导航固定 Bootstrap；旧 navigation1/2 继续按原 pin 使用 Skill。模型显示精简、用户约定原位迁移及项目显式质量阶段策略已进入同一源码候选，完整规则/有序引用/义务和原采用事务保持；未启用质量策略的项目继续原行为，专门权限和发行门不由可选阶段豁免。源码功能、共同版本资格与显式项目采用分别取证。

这些能力已进入候选实现，不能继续列作完全未实现的未来方向；其局部测试或局部审核也不能替代最终完整套件、独立整版审核、Owner 接受、固定分发、宿主安装和项目采用。当前各项最终门禁尚未完成，真实能力与证据限制取版本说明。

当前候选已加入[产物分类与问题驱动改进方法](versions/2.0.0/knowledge/README.md)、任务内最小责任与知识维护接点，沿原索引和全文查询消费。内容、机制、实际应用和自然复用分别取证，不从两篇文档推出专业效果或降本。后续仍包括自测失败后续修合同评估、支持起点的完整升级/恢复与剩余生成入口一致性验证。自然宿主触发、发现和加载需要实际观察，不能由静态检查代替。

## 后续方向

- **共享专业内容**：游戏、媒体、小说或软件领域可独立维护流程、规范和方法；产品项目自行决定采用，不继承供给方权威。当前来源与采用机制可作为基础，新增组织能力仍须真实消费者需求。
- **链式版本适配**：在实际格式或语义转换点提供累积适配器，并声明受支持的旧起点。当前特定升级桥不代表任意跨版本链已实现；项目升级继续保留原动作收口、恢复及入口切换边界。
- **问题驱动的持续改进**：在真实任务中检验学习内容的责任归属、适用条件与后续消费，避免将未经验证的建议升级为全局规则或常驻服务。

## 有真实证据后再评估

- 宿主提供可信的正文成员、身份或权限信号时，再评估跨请求加载与真实性核验；当前不以摘要或旧收据证明全文仍在模型输入中。
- 跨平台运行、发行证据复用、模块独立发布和更强并发迁移，分别以实际消费者、平台证据、重复成本或不停机需求决定范围。
- 自动索引、后台同步及更广的知识扩展，先证明现有显式来源与查询不足，再决定是否实现。

不建立中央消费者采用表、父项目继承引擎、第二意图服务或自动项目升级。1.16.0 既有目标与变化保留在其版本资料和 Git 历史；新版本方向不改变旧固定包和现有项目的采用事实。
