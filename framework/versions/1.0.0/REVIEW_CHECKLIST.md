# 审核清单 v1.0.0

审核人必须独立读取任务卡、权威资料和实际差异，不把执行者总结当作证据。结论只有 `APPROVED`、`CHANGES_REQUESTED`、`BLOCKED`。

## 1. 审核输入

- 任务目标、非目标、风险等级、文件所有权是否明确。
- 工作树是否有其他会话改动，目标差异能否与其区分。
- 变更前行为、目标行为、权威文档和验收标准是否一致。
- 执行者是否提供命令、输出摘要、失败项和未验证项。

## 2. 方案审核

逐项判断：

1. 是否服务项目核心原则和真实用户体验。
2. 是否符合分层、依赖方向和公共契约。
3. 是否只有一个真相来源、一个状态所有者和明确生命周期。
4. 是否存在更简单且不牺牲正确性的方案。
5. 是否能扩展而无需复制分支逻辑。
6. 是否产生隐藏耦合、循环依赖或跨层直写。
7. 是否过度设计、提前抽象或引入无验证价值的状态。
8. 持续时间是否优先由时间戳/事件推导，而非易漂移的逐帧累加。
9. 同类概念、错误码、命名和数据形状是否统一。
10. 对上下游文档、测试、配置、渲染和工具链的影响是否闭合。
11. 方法是否单一职责，查询与修改是否清楚分离，抽象层级是否一致。
12. 新增持久字段能否由现有事实推导；若能，通常不应保存。

## 3. 文档审核

检查：最新设计、层级归属、上下游一致、场景完整、生命周期闭环、数据流可追踪、编号/链接/编码正确、文内与文间无冲突。用 `rg` 搜索旧概念和新概念的扩散范围，并检查 UTF-8、U+FFFD、NUL、截断、代码围栏、尾随空格和 `git diff --check`。

## 4. 代码审核六层

1. 语法/静态检查。
2. 文件完整性与编码检查。
3. 旧概念和废弃入口在应覆盖范围内被清除。
4. 新合同、直接测试和必要运行时路径存在。
5. 逐条把设计行为声明映射到实现与测试证据。
6. 质量检查：热路径分配、死代码、命名、重复、魔法量、断言、职责、复杂度和拆分边界。

再运行任务相关专项测试、全量回归、构建和必要的视觉/浏览器验证。构建通过不能代替运行时或视觉检查。

## 5. 偏差等级与结论

- 架构性偏差：职责、依赖、所有权、公共契约错误。阻塞批准。
- 机械性偏差：遗漏、错误实现、测试缺口、文档不一致、格式/链接导致工具失败。阻塞批准。
- 卫生性偏差：不影响当前合同的局部整洁问题。优先当批修复；若延期，必须绑定负责人和任务。

`APPROVED` 要求 0 架构性偏差、0 机械性偏差，并列出已验证范围和残余风险。审核人不得直接替作者悄悄修复后自批；若审核人修改了实质内容，应回到另一个合格审核人复核。
