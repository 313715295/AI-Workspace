# AI Workspace router

This Skill is Framework-managed navigation and is `NON_AUTHORITY`. Repository-local Bootstrap, the exact project pin, current Controller/task objects, project corrections, process policy, action packages, product files and observed evidence remain authoritative.

## Activate

Activate on a project-relevant user prompt, task or authority-context change, compaction/resume/handoff uncertainty, the natural pre-action boundary, and the natural pre-output boundary. Reuse unchanged bound context. Do not activate for every tool call or ordinary unchanged-context step. Explicit `$ai-workspace-router` is the manual recovery route; unobservable invocation retains `INVOCATION_UNPROVEN`.

## Navigate

1. Fully follow `.ai-workspace/BOOTSTRAP.md`; bind the real Maintenance control root, Framework target root, exact pin/backend, release seal, Controller, task, actor/role/phase/profile, identities and protection boundaries. Recovery grants no action.
2. Keep control and target repository facts separate. Reuse source composition only while every bound project/pin/seal/Controller/task/actor-route/corrections/policy/config/capability identity is unchanged.
3. Form the ephemeral intent-only `IntentEnvelope`; use pinned `PROCESS_REQUIREMENTS_RESOLVE` to mechanically form `AuthorityContext`, select three-source rules and return complete canonical text beside the original prompt.
4. Use `ADMIT_ACTION` before governed actions and `FINALIZE_OUTPUT` before final delivery. UNKNOWN or drift blocks or conservatively loads; mechanical PASS proves structure only.
5. Preserve independent packages for source, test, Review, OWNER_ACCEPT, Git, push and external actions. Never use this Skill or a resource route to grant or merge them.

Default intent interpretation uses the current main-model turn and adds no independent call. No per-tool hook, persistent cache, service, registry, poller or ledger is created.
