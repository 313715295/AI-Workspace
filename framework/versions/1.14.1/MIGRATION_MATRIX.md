Adoption is project-owned. Preview must report exact incorporated, retained and conflicting corrections before pin projection and recheck after projection. Records are never deleted by upgrade.

Existing two-field 1.11/1.12 task routes remain readable with `LEGACY_ACTOR_CONTEXT_UNBOUND`, but cannot authorize a substantive actor action. For the current active task only, `upgrade-project.ps1` accepts its exact repo-relative path, whole-file identity and authenticated actor, then requires one current Controller package over the complete deterministic upgrade write set. It projects the target pin and every non-task object first, atomically advances the task schema plus `actor/role/phase` last, performs no later write and stops for immediate target-version FULL_COLD. Fixed repository-resident recovery material resumes only forward, reconstructs the original authorized path/preimage set, rejects traversal or extra objects, and requires the package's Controller ID/epoch/object identity still to match the current Controller. Controller rotation requires a fresh recovery authorization. There is no bulk task rewrite or actor inference.

All repository-resident upgrade preparation, active transaction and retained recovery paths are target-version deterministic and emitted by preview as `UPGRADE_WRITESET`. New registration likewise emits deterministic preparation/active/recovery locators plus `REGISTRATION_WRITESET`; it renders and validates under the deterministic same-volume preparation locator outside the repository, then atomically promotes the complete state-bound transaction as the first repository write. Recovery requires the state transaction ID and destination to equal those trusted preview-derived locators; stale state cannot select another repository path. A verified active recovery reconciles a known-empty leftover preparation directory, while unknown non-empty bytes still block. A caller can therefore bind the complete path set before `-Apply`; no post-start GUID creates an unannounced repository path. Registration, ordinary upgrade and actor-bound recovery enumerate the physical transaction tree and require exact equality with the state-bound old/new/state closure before promotion or any live write; an undeclared file or directory stops with the transaction retained. Managed `AGENTS.md` projection preserves every byte outside its markers; non-LF or missing-final-LF project content is rejected before any transaction rather than normalized. Every existing component of `AGENTS.md` and `.agents/skills/ai-workspace-router/SKILL.md` must be repository-contained, correctly typed and non-reparse at preflight and immediately before a managed write or deletion; recheck drift retains the transaction and stops without out-of-repository mutation. System-temporary read-only projections are not project authority and are deleted by the checker.

Moving permanent rules from `PROJECT-CUSTOM` to `.ai-workspace/process-policy.json` is a separate project transaction binding config, Bootstrap and policy pre/postimages. Registration and the direct 1.11–1.13 adoption route may create the empty carrier, but they never move a legacy rule into it automatically.
