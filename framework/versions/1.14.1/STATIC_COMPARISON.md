# Framework 1.13.0 versus 1.14.1

| Concern | 1.13.0 | 1.14.1 candidate |
|---|---|---|
| Tool Contract/backend | platform-neutral contract; official `powershell7`; Windows evidenced | preserved; adds one process-requirement operation |
| task context | authoritative role/phase; legacy fallback | exact host actor + role + phase; old two-field tasks carry an actor-unbound ceiling |
| applicable process rules | loader selects Framework modules; corrections evaluated separately | one composer progressively selects across Framework, still-effective corrections and project policy |
| pre-action boundary | action-specific authorization/checkers | adds structural preparation decision; independent authorization remains mandatory |
| pre-output boundary | task/review/terminal rules in modules | adds structural result and delivery decision; semantic correctness remains unproven |
| correction absorption | cumulative correction-ID coverage plus normative/test/Review proof | requires exact alias/native/catalog/source-record mapping before suppression |
| permanent project rules | `PROJECT-CUSTOM` | keeps legacy authority; adds one structured carrier reached only by reviewed atomic migration |
| caching | task-bound loaded workset reuse | one ephemeral source receipt reused by ADMIT/FINALIZE; no persistent cache or ledger |
| host enforcement | instruction/mechanical ceilings | explicit `HOST_ENFORCED`, `FRAMEWORK_GATED` or `INSTRUCTION_BOUND`; no repository-only physical-enforcement claim |
| added machinery | existing control objects and tools | one catalog, one shared composer, one front door, one optional project carrier; no role/task/service/queue/registry/ledger |
| release evidence | conformance + independent Review + seal | preserves those gates; optional post-release project observations inform later improvement without blocking release |
