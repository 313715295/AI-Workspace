# Framework 1.13.0 change log

Baseline: immutable Framework 1.12.0. Release class: `MINOR`.

## Added

- one `PROCESS_REQUIREMENTS_RESOLVE` Tool Contract operation with `DISCOVER`, `ADMIT_ACTION` and `FINALIZE_OUTPUT` modes;
- one sealed native process-requirement catalog and one shared `ProcessRequirementComposition` backend;
- strict task-bound `actor + role + phase` routing for schema 1.13.0 task cards;
- one optional structured project process-policy carrier for new projects and reviewed migrations;
- canonical legacy-correction record identities, exact alias-to-native absorption mappings and PowerShell/Node identity fixtures;
- non-authoritative post-release observation guidance for projects that explicitly adopt 1.13.0, using normal task evidence without synthetic sample work or a Framework release gate.

## Changed

- the legacy correction checker is now only a compatibility view over the same source composer;
- process discovery composes Framework rules, still-effective corrections and permanent project rules conjunctively while preserving their separate authority;
- historical correction-ID coverage cannot suppress a 1.13 correction without an exact source-bound mapping;
- action authorization binds the current task whole-file identity and host actor in addition to its existing path/object/config bindings;
- new registration writes schema4 project config plus an empty process-policy carrier; direct upgrades retain schema3 and `PROJECT-CUSTOM` until a reviewed project-owned migration.

## Preserved

- the Framework 1.12 Tool Contract and official Windows PowerShell 7 backend;
- immutable older releases and project-owned version pins;
- owner-first routing, healthy WARM rebind, compact non-interrupt delivery and project correction retention;
- independent SOURCE_WRITE, TEST, REVIEW, OWNER_ACCEPT, GIT, PUSH, BROWSER, DEVICE, EXTERNAL and protection gates.

## Not added

No second effective authority, actor or Reviewer pool, trigger registry, merged policy projection, service, poller, ledger, per-tool reload/hook, automatic correction rewrite, automatic project upgrade or host-enforcement claim.
