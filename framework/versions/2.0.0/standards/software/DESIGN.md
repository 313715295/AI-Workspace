# 软件设计与接口

适用于项目已采用本标准的软件方案、接口、数据模型和架构变更；生产和审核共同遵循，按实际改动取证，不要求每个小修复重写架构文档。

- 从实际调用者和输入输出说明问题：改变前哪个有效场景失败，改变后应得到什么结果。区分公开接口、内部实现和用户可见行为，不把测试便利提升为公开合同。
- 为每个被改变的接口核对直接生产者与消费者、调用顺序、错误语义和失败返回。涉及兼容性时给出受支持的旧/新组合及迁移边界；没有真实消费者的假设兼容层不进入默认方案。
- 状态和配置有唯一写入责任与语义来源。能由当前权威稳定推导的字段避免重复持久化；确需缓存或副本时明确失效条件及重建方式。
- 数据或生命周期变更覆盖创建、更新、取消、中断、恢复及释放中实际受影响的路径。说明失败会停在哪个可识别状态，以及如何恢复；不能用“成功路径可运行”代替中断设计。
- 依赖方向和职责分界使局部修改可被核对。比较复用现有实现、标准库和必要新代码的代价，依据真实约束选择；不为没有调用者的未来能力添加服务、层级或配置。
- 设计审核用最强反例检验方案，例如异常输入、并发变更、旧数据或缺失依赖。结论绑定具体对象和可验证结果；同一根因合并处理，未证明假设保持显式。
