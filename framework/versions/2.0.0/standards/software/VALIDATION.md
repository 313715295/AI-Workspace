# 软件验证与回归

适用于项目已采用本标准的软件实现、测试方案及其审核；验证深度跟随实际风险和变化，不靠测试数量证明质量。

- 从预期行为和真实失败设计用例，至少让关键错误实现可能失败。只复述实现分支、mock 掉待验证机制或核对文案存在，不能证明行为正确。
- 修改公开接口或数据合同后，覆盖直接消费者、失败输入和实际受影响的相邻回归。未受影响且身份/依赖仍有效的证据可复用；是否扩大测试取决于新失败或未解风险。
- 测试隔离真实项目数据、外部副作用和共享状态。必须访问真实环境时依其授权执行，夹具与真实宿主、设备、服务结果分别标识，不把模拟返回当实际观察。
- 保留实际命令、退出码和必要原始输出。失败、中断、未运行、跳过和未知分别报告；修复后的通过不抹去原失败，不重复累加重跑数量。
- 浏览器、设备、性能、持久化或并发是交付要求时，用相应直接验证覆盖；单元测试、静态检查和人工推断只能证明各自范围。
- 审核先检查测试是否能推翻错误方案，再检查结果。总结行为覆盖与剩余限制，避免无实际消费者的重复测试、无理由整套重跑及为了报数添加低价值断言。
