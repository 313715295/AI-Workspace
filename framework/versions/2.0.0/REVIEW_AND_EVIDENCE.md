## 风险跟随 action

LEGACY中的public contract change、candidate payload、Controller/long-lived owner switch、material scope的Git integration及profile要求的external沿原独审门。EXPLICIT普通成果取同一稳定qualityBinding及仍有效专业/用户要求；专门发行、采用、source publication、external或保留决定的显式独审不能由普通C空集合覆盖。实际独立Review在所有profile都须完整排除Owner、issuer、writer及全部贡献者。

mechanical formatting、canonical projection 与 release-field sealing 在不改变已 Review 的 public contract 或 candidate payload 时，可以使用直接 checker evidence。

Review 不授予 write、Git、push 或 external capability。

<!-- AIW-REQUIREMENT:PR_REVIEW_QUALIFICATION_AND_PLANNING:BEGIN -->
常规评价不自动成为独立审核。按任务要求与风险判断目的、范围及资格；讨论是否需要审核用NONE/PLAN，不伪造候选冻结、自检、分派或未来裁决。实际REVIEW_ROUTE消费准备，REVIEW_EXECUTE交付真实verdict。生产者和审核者对同一成果共同消费适用质量要求，按真实产物/工作分类加载已采用专业标准；目录中存在标准不等于采用。

独立Review使用可见APPLICATION_TASK，绑定真实主体、完整原始材料、当前精确候选及可追溯结论。新独立审核用新会话，同一审核/修复复审可复用仍独立且上下文可用的原会话；改名、继承writer判断或返回摘要不证明独立。所有profile实际独立审核都完整绑定并排除Owner、issuer、candidate writer及全部material contributors，STANDARD/MICRO同样执行。贡献者集合变化重绑，接收者只承担自身审核，不另派Reviewer。

冻结候选绑定精确对象、字节、适用要求、原始证据、writer释放和证据上限；实际Git候选另绑定仓库、baseline及index/dirty，不为非Git成果虚构commit。规范证据只保存一份原件，其他对象引用，不能在可变卡之间复制通过状态。

审核针对实际风险寻找足以推翻错误方案的反例，结论绑定对象和证据。实际需要时在原审核材料或检查记录保留已核对象/范围、语义判断及依据和适用条件、证据引用与未完项；已有记录充分则直接引用。压缩恢复仍按现行合同补齐当前全部命中完整规则，并核对当前候选、范围、依赖及依据后承接仍有效的工作；变化或依据不足时复核受影响判断及关联部分。记录不证明当前持有全文、判断正确或已完成审核，不追认未准入阅读；最终同一Reviewer仍负责完整覆盖、跨项冲突和质量结论。同一根因合并finding，保留原因、影响、最小修正和必要定位，不凑视角、编号或数量。需要方法帮助时可按需读PERSPECTIVE_LENSES或已采用专业标准；方法选择不另成为准入/回执义务。

正常交审顺序唯一取PR_REVIEW_ROUTE_PREPARATION。真实finding直接交仍负责修复的writer，finding本身不授写权；当前修复包准入后修复，由原仍独立Reviewer按受影响范围复审。实际修正、直接消费者和必要相邻回归须复证，未变完整Review与有效证据保留；扩面或决定/主体变化回Owner。提出finding不自动成为贡献者，测试通过不取消有效质量问题。

APPROVED由Reviewer一次直交原Owner/有权接受者，携交审前已备齐的候选、验收映射、测试、限制及产物去向引用，不让writer再转相同通过结果。Reviewer不改Owner卡、STATUS/index，不删Owner包，不等释放/ACK；终态与真实发送遵循TASK/HOST。Review与RESULT_ACCEPT分别成立。

<!-- AIW-REQUIREMENT:PR_REVIEW_ROUTE_PREPARATION:BEGIN -->
实际交审先完成本轮真实生产/自测FINALIZE、适用质量选择要求的当前成功自查、候选冻结和最终消费者所需完整材料。LEGACY/选中或另有必需SELF阶段时仍需作者成功SELF；C无SELF分支以TOOL_CONTRACT的productionFinalizeRef及完整候选准备成立，不伪造作者PASS。历史失败保留但不冒充当前成功集合；不能挑PASS避开同集合FAIL/INCOMPLETE。文档语义自查可用有实际依据及上限的MODEL_JUDGMENT，适用软件测试须有真实COMMAND的命令、退出码和输出引用，义务名称不代替证据。

随后以最终当前任务/候选校验分派者的REVIEW_ROUTE权限，用真实REVIEW_ROUTE+HANDOFF意图取得必要组织、Review和HOST完整正文并ADMIT；相同目标健康选择可复用，旧SOURCE/TEST选择不能替代新分派。作者身份、适用成功SELF或真实生产原F及当前候选的共享检查在ADMIT、创建未知Reviewer之前完成，并在实际发送收口复用：作者取原repairReviewPlan.writer或当前纯Review包的candidateWriter；Owner可组织另一作者的候选，但不能用Owner自己的SELF替代作者SELF。Reviewer ID尚未知不妨碍核对这些已知事实；缺作者绑定、必需SELF失败/错人、无SELF缺原成功生产F或候选漂移先拒绝，不创建会话后才发现。SELF的requirementsRef与实际适用要求仍须实质核对，结构通过不证明语义。非Owner writer只可沿原Owner预授的continuationPlan/repairReviewPlan和真实后像承担有界准备，不取得Owner或转授权。只有包绑定的任务事实实变且必须先更新才由有权者更新卡；产物实际生成由生产FINALIZE和冻结材料证明，不因旧生产前叙述向Owner反向索卡写权。

纯接收者REVIEW_EXECUTE包绑定最终任务、完整候选、原始材料、资格及直接消费者。已知Reviewer用真实ID；新建且ID未知时，按HOST/TOOL的不可执行待绑定原件一次交齐初始委派，接收者核对原始人类来源和自身真实身份，独立完成checker/DISCOVER/ADMIT。准备态不是执行许可。委派明确finding直writer、APPROVED直Owner；上游agent的“留本会话待读取”不能改写原人类交付安排，只有真实用户改变消费者才用TOOL的对应例外。

有限生产集M可按原预批reviewScope交审完整A。M成功后像须来自实际生产/测试FINALIZE，A中未改对象逐项复证原冻结字节或缺失状态；重hash当前M不代替成功收口。真实TEST_RUN的SELF/COMMAND绑定M；LEGACY/选SELF的完整准备SELF绑定A并引用前者。C无SELF准备直接核原成功生产F与完整A，不借当前重hash取代。A不扩SOURCE/TEST/REPAIR写权；未改对象漂移、finding所需写集超M、实际扩面或新决定才回Owner，预批范围内直接修审，保留原有限周期及未变证据。具体包/工厂/continuation字段唯一取TOOL_CONTRACT。

writer交齐完整材料后结束本轮，仍承担原范围内真实finding修复，不向无下一动作的Owner发中间终态。REVIEW_ROUTE结果证明真实分派，不要求未来verdict；REVIEW_EXECUTE才产生实际审核结论，接受/Git/发行/采用仍独立。

<!-- AIW-REQUIREMENT:PR_EVIDENCE_CEILING_DISCIPLINE:BEGIN -->
证据只支持实际观察到的对象、环境、机制和范围。夹具可证明通用协议、失败分支、规范身份和匿名项目保持；自然项目观察另证明其真实调用、误阻断/泄漏及有覆盖的成本，二者不互相冒充。可选发行后自然观察不自动成为新的发行门。

结构PASS、hash、调用返回或模拟宿主均不证明语义正确、模型attention、真实浏览器/设备状态、远端发布或外部动作完成。失败、中断、未知、跳过和未运行明确保留；平台支持只按对应实际conformance声明。时间、字段和规范结果的实现要求取TOOL_CONTRACT及TOOLCHAIN，不把未验证平台写为已支持。

<!-- AIW-REQUIREMENT:PR_RESULT_ACCEPT_SEPARATE:BEGIN -->
RESULT_ACCEPT独立接受精确成果，默认由当前Owner完成。受托人须有原Owner签发的纯接受包，或当前真实人类对该项接受的明确授权；Controller头衔、父任务或Reviewer通过不代替授权。接受不追溯改变Reviewer独立性，也不授予实现、Git、push、external、安装或采用权限。

真实接受动作始终加载本要求，不因role/phase/profile遗漏。按TOOL_CONTRACT绑定候选、适用要求、实际前置证据及用户保留决定；LEGACY普通无计划Owner接受沿原无扩展分支，CRITICAL绑定原独审；C普通接受取同一有效RESULT_REVIEW和显式专门要求，保原acceptanceBinding及实际前置。实际输出使用RESULT_ACCEPT动作与typed RESULT_ACCEPTANCE，不能用NONE或记录写入冒充。

有验收阶段计划时只消费当前阶段的真实传递前置；后置用户门约束SUCCESS及后续动作，不倒置为内部接受前置。机械校验只证明身份、对象和所需回执一致，不证明判断语义。审核/接受读取足够原始证据和真实退出结果，摘要不替代原件；自检及交审成功条件取PR_REVIEW_ROUTE_PREPARATION。
