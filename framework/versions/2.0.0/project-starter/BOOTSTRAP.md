2. 从project pin及原采用记录定位唯一固定runtimeRoot，验证原完成来源和TOOLCHAIN；未完事务沿原健康入口恢复，未知或漂移不转开发目录。具体恢复与来源消费取该固定版本RECOVERY_CORE，必要接入分支取根PROJECT_ADOPTION。
3. 已知taskId直接读当前卡，未知才用tasks/README定位，STATUS按实际全局事实需要读取；绑定真实请求/责任/动作/范围。无适用任务的合法只读问题使用PROJECT_READ_ONLY，不造假卡。

5. 每个真实受治理动作满足授权checker及ADMIT；已证明等价的普通schema1由ADMIT内原完整checker满足，省外部重复命令，schema4/专门路径未证仍分别调用。正式结果按实际证据与消费者FINALIZE，只有TOOL_CONTRACT的当前USER无包无副作用普通NONE答复窄例外可省机械收口，不造收据；范围/权限/来源变化按命中规则处理。具体输入、schema、continuation、控制转换及临时生命周期唯一取TOOL_CONTRACT，不从模板推导权限。

项目事实、专业标准和知识依项目原采用管理；未采用可选内容不自动加载。真实Git、设备、外部、Review、接受、发行和采用保持独立门。健康续作不因一次工具调用重跑完整恢复；失败/未知只报告具体边界和下一动作。
