# 表现反馈与权威模拟分离

METHOD / REFERENCE_ONLY；内容版本 1；适用于有动画、网络延迟、插值或预测的交互。这里的权威指项目明确指定的最终游戏状态写入者，可在本地，也可在服务器；不预设所有游戏都采用服务器架构。

先列明生命、伤害、库存、碰撞与成功判定由谁写入。渲染读取已确认状态，按需增加可撤回的视觉预期。命令带可关联标识；确认、拒绝与重复结果各有处理。表现可以先出现，权威写入只在指定路径发生一次，动画结束或屏幕位置不能无意成为第二个伤害/库存来源。

Unity Netcode for GameObjects 2.2 的 client anticipation 分开视觉值和服务器权威值，并支持纠正与平滑；该机制限定客户端—服务器拓扑，文档明确其并非完整的回滚重演预测。这是职责分离的实例，不能据此宣称自有项目已具备网络预测能力。[Unity Client anticipation](https://mp-docs.dl.it.unity3d.com/netcode/2.2.0/advanced-topics/client-anticipation/)

建议先做最小实验：同一条攻击命令在正常、低帧率、长动画、无表现层、重复确认及拒绝响应下执行。检查伤害/库存变化次数和结果一致性，再检查视觉延迟、纠正跳变和音效重复。画面看起来命中与模拟实际命中是两项证据。

单机战斗也可复用此思路：模拟产生命中事件，表现系统消费事件并标记已消费；取消动画不倒推出已确认伤害不存在。若设计明确使用动画标记决定攻击窗口，则让模拟显式消费该标记并处理暂停、跳帧和重入，不能假定所有动画事件都只能是装饰。

代价是命令/事件关联、取消路径与少量中间状态。对即时且无延迟的简单界面，直接在一次事务后更新显示更便宜，无须引入预测服务。反例：为避免视觉跳动而直接改权威位置，会让相机平滑反过来影响碰撞；为追求分离而复制整套模拟，又会增加一致性成本。
