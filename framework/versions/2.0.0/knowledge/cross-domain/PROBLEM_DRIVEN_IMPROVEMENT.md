# 问题驱动的学习与改进

本文是可选 METHOD，contentVersion=1，由 Framework 内容维护者维护。用于真实失败、专业不确定性、知识不足或重复误判后的诊断与改进。它是学习内容、来源选择、核实、应用与复用的完整方法正文；核心任务责任仍取 TASK_AND_SCOPE，知识归属和维护边界取 KNOWLEDGE_AND_REFERENCE。阅读本文不新增授权、采用或强制研究阶段，也不要求启用方法库。

内容为通用原创整理，匿名化案例用于挑战错误结论，不是本次观看、听审或行业试点证据；未宣称专业效果、自然触发或降本已证明。材料出处、专业解释、待验建议和实际效果始终分开。

## 先判断缺的是什么

在原任务说明预期与实际的差异、对象版本、场景、影响及证据。用户反馈能证明某种体验或诉求，不一定证明原因；日志只证明采集范围；作者解释仍可能是假设。无法复现也保留实际反馈和不确定性。

先看现有事实、方法和能力：已知缺陷直接修，应用偏差纠正用法，缺资料补必要材料，缺工具或验证能力安排相应能力，真实规则冲突只停止受影响决定。不要把每个问题统一变成研究任务。已有知识充分且适用时直接应用；明确的播放器速度设置错误不需要系统研究电影理论。

问题驱动允许系统补基础。若不能解释现象或判断专家建议，就补连贯单元：先修概念、原理关系、有边界的例子，再回到实际问题。Owner 在原任务确定与目标相关的范围及资源，专家可帮助形成学习路径；不另设学习主管，不按书本数量、考试或整门学科覆盖率验收理解。

## 学什么

以下六类是按缺口选取的导航，不是逐任务必学清单，也不按类别拆任务。

| 内容 | 何时有必要 | 应回到原工作形成什么 |
|---|---|---|
| 专业原理与基础 | 概念或关系不清，无法解释现象，相似错误反复出现 | 能解释机制、区别易混概念和边界，并据此修正判断 |
| 质量标准与判断 | 不知道正确、好或可用的条件，误套另一用途的标准 | 区分现行要求、行业建议与用户偏好；新标准不自动替代已采用要求 |
| 设计与实施方法 | 能描述问题，但缺可执行解法或路线取舍 | 明确步骤、前提、失败模式和恢复，落实到具体改动 |
| 验证与评价方法 | 现有检查回答不了疑问，观察被过度外推 | 知道需要看、听、测或运行什么，控制重要干扰，保留未覆盖部分 |
| 工具与能力边界 | 输入、版本、限制或可观察能力不清楚 | 区分功能声明、当前配置、实际可调用、实际成功与有效结果 |
| 案例与失败经验 | 相似情境下需要理解例外、避免已知误判 | 比较对象与条件的关键异同；失败经验不简化为万能禁令 |

例如“动作慢”可能涉及动作/表演基础、时间评价和工具控制，不能只收集提示词技巧。若基础足够而工具无法观察时间过程，继续读资料也不解决能力缺口。

## 从哪里取得依据

| 来源 | 用途 | 必须辨明的限制 |
|---|---|---|
| 项目资料与反馈 | 当前需求、产物、日志、数据、用户反馈、决定和失败 | 版本、环境、实际观察与解释分开，历史决定不替代当前决定 |
| 已选方法和共享库 | 项目专业正文、随包方法或行业库，优先复用适用的现有知识 | 核对完整方法、必要依赖与版本；已采用标准与参考方法效力不同 |
| 外部专业资料 | 标准、官方文档、教材、论文、可靠实践或课程 | 原始出处、实际可得正文、版本、条件和方法；摘要、转述和宣传不等于完整研究 |
| 专业人员或专家 | 解释、比较、诊断、有经验的判断及具备能力的观察 | 交付依据、推理、条件与待验项；头衔、模型档位和自信不证明效果 |
| 试验与复盘 | 比较解释、验证方法、识别当前环境限制 | 对象、输入、环境、观察方式和干扰决定证明范围；有输出不等于成功 |

来源不是固定可信度排名。规范效力、事实真伪、解释合理性和方案效果是不同问题。原始资料用于核查作者实际主张，可靠综述与教材可建立脉络，不因二手而一概排除；但据转述不能声称自己读过原文。工具版本承诺要看对应正式说明，审美或使用效果还需要目标情境反馈。

模型已有知识可用于稳定概念解释、检索方向或假设，未核查时不能声称已读某书、论文或已确认当前工具行为。足够稳定、低影响并可直接验证的判断不为形式强制联网；关键、陌生、时效性强或冲突判断按需要补原始资料或实际验证。专家引用也不自动计作接收者已读。

## 核实、冲突与进入应用

先明确待支持的主张：确认事实、解释原因、判断现行要求、选择方案，还是证明效果。核对出处、作者/机构、版本/日期、条件、术语和证据方法。在引用处保留实际读到的章节、段落、摘要或媒体区间、用途与缺失部分；只读摘要只能给有界判断，方法与样本影响结论时须补对应正文或说明采用了其他资料，不能猜未取得内容。每题读完整本书不是前置，基础不足也不能靠摘要拼接冒充系统理解。

遇冲突先比较对象、版本、环境、评价目标与观察方式。“官方说明支持”与“当前配置调用失败”可以同时成立。同条件仍矛盾时，保留双方主张和证据，选择最能区分它们的原始材料或有界试验；不按搜索排名、新旧日期、赞同人数或专家身份裁决。

参考建议不能自行撤销当前已采用规范。真实目标/规范冲突沿原 Owner 和变更门处理，只停止依赖它的链；反馈可改变目标判断，但不能倒造专业验证。工具缺少读取、观看、听取或运行能力时，安排有相应条件的人或工具，或只作限定结论；不以文字描述、指标或配置替代未发生的观察，不把全部验证默认转嫁用户。

资料足以支持当前有界选择，且有可行的对应验证与恢复时，就进入应用。说明采用哪部分、为何适用、哪个判断或产物改变、预期改善、什么结果会否定它；在试验前形成预期，保留基线和恢复办法。未在本场景证实的方法是候选试用，按现有授权与风险边界实施，不能提前标成有效或全面采用。重大专业假设未解，只暂停依赖它的决定；不无限扩展研究。

## 在原任务完成闭环

原参与者有足够上下文、专业和验证能力时，直接完成诊断、应用、自查与有价值的沉淀，Owner 持续负责。专业判断困难、跨域冲突或独立成果确有收益时再安排有界专家；不要求低档先失败，不因“学习”固定最高配置，也不建立常驻学习队伍。

专家输入一次交齐目标、问题、对象与失败证据、已试路线、适用要求、验证条件、精确输出、直接消费者和限制。输出区分文献依据、经验、实际观察和假设，给出可执行取舍及验证办法，不能只列原则和链接。专家可以承担困难实现；Owner 须能理解、处理冲突并消费结论，能力不足沿原资源或受托接受安排处理，不能机械抄录“专家说了”。

实际验证者同时需要专业和工具能力；独立审核还须符合原独立性门。贡献者可以自查，不能独立审核自己的成果。具体方法的已知依据不替代本对象验证：设计关系可用文字/图审查，节奏需动态观看，声音需听取，软件行为需运行。Owner 比较预期与结果，决定保留、调整、回滚、继续查证或结束。存在混杂因素就保留归因限制，不从一次变化冒称因果或普遍规律。

失败、中断或来源不可达时，保留对象、已取得的证据、待验假设和唯一下一动作，沿原任务恢复并复用有效部分；合法替代材料注明不是原作全覆盖。负结果也可保留，不必为了沉淀等到“成功”。

## 两个匿名化反例

**静帧被当成节奏证明。** 一组粗格已经让人物位置关系可读，检查者据此声称成片节奏正确。该证据只能支持空间或构图判断，没有证明动作时长、衔接、声画关系。先明确疑问属于设计关系还是时间表现；后者需要匹配版本的动态观看，声音问题还要听取。不能为填验收表而把静态推镜叫角色运动。这是证据类型纠正，不是要求每份概念图都制作视频。

**把“动作慢”一律归因于提示词。** 模型产出片段后，作者根据供应商指南和专家建议改词，却未比较实际播放、输入条件与工具控制，便宣布改善有效。应先区分播放器设置、动作设计、工具控制上限及主观目标。已证实的设置错误直接改；确有知识缺口才学习相关内容，设计可反驳的比较并实际观看。专家建议能形成候选路线，不能独自证明效果；有结果文件也不证明完成了运动或节奏验收。

这两例不包含私有素材、路径或用户事实；不代表当前任务已重新播放媒体，也不把一次失败提升为禁止所有类似工具或方法。

## 保存、发现与下一次使用

材料不等于知识，知识条目不等于有效方法。书籍、课程、网页和专家意见先是出处；完整读到某论证只支持相应阅读声明。结合条件形成方法解释，才可作为候选方法；实际应用与对应验证才支持“在这些条件下有实际效果依据”。索引 CURRENT 表示维护/依赖状态，不是效果等级；这些区别用原记录与正文表达，不新增评分或状态 schema。

| 内容 | 既有归属与后续入口 |
|---|---|
| 本次阅读、诊断、试验、用户反馈及专家原意见 | 原任务/作品记录；有价值时由完整方法链接匿名或获准案例 |
| 项目当前结构、约束和事实 | 项目权威正文；需要派生入口时用 PROJECT_DERIVED 及真实依赖 |
| 可复用行业方法、条件和反例 | 有维护责任的项目专业正文或共享 METHOD，保留依据及未证范围 |
| 跨行业指导 | Framework 相应可选方法载体，按内容与发行边界交付 |
| 需要约束以后工作的真实义务缺口 | 原规则/标准采用或纠正流程；已覆盖则补案例，不再复制规则 |

同一观点已有完整正文时补条件、反例或案例链接；不复制第二篇“最佳实践”。无需新增价值时直接引用旧结论。项目私有事实放入共享目录也不会变成通用事实；通用包只承载可公开整理。问题解决、知识整理、下次实际应用是三个完成项；本次关闭不无限等待下一次事件，“自然复用已证”只在真实证据出现后成立。

原 README/业务入口和库索引说明“遇到什么问题时读它”、适用条件、版本及维护入口。不要把专业基础切成只靠关键词命中的碎片；选择后读足够完整的方法和必要依赖，再按问题深入。已知合法专业文档可直接阅读，不强制先注册库。显式知识 QUERY 使用已选 SourceId，默认定位，FULLTEXT 才返回正文；不全库扫描，标题、摘要和 hash 不代替需要的正文。方法引用不能补漏必须规则。

本地文件、远程库和引文 URL 分别处理：位置、许可、可达、完整获取、实际阅读、应用效果与规则采用逐项核对。引用 URL 不是库接口，不自动抓取或注册 sourceBinding。合法临时阅读一篇资料无需先建知识条目；持续供给确有需要才按项目决定接入索引/来源。Git/HTTPS provider 只提供合同声明的内容读取，不能据此推断能登录私有库、取得所有附件或看听任意媒体。本地资料足够时不强制联网；PINNED/FOLLOW 与单查询快照保持原合同。

参与者在原方案说明采用或不采用哪部分、理由和实际改变。单纯增加引文不证明有效应用；有依据地判定不适用也有价值。维护者收到新来源或反例，核对适用影响，更新正文、contentVersion、索引身份和当前入口；需要时撤回或标 STALE/HISTORICAL，保留旧冻结证据。旧日期不自动失效，新版不自动适合固定旧环境。PROJECT_DERIVED 按真实依赖与影响检查维护，其他项目是否更新/采用由各自决定。
