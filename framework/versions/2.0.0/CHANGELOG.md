# Framework 2.0.0 变更记录

## 项目预授权直接调用与原外部结果补充（源码候选）

- policy3增加可选externalAuthorization，缺省PER_ACTION保留旧行为；PROJECT_PREAUTHORIZED引用已有项目许可正文，范围内使用原工具，免逐次任务卡、EXTERNAL包和模型D/A/F。真实完整加载显示当前模式与全部适用许可；无任务外部请求用PROJECT_EXTERNAL，不冒充只读NONE或借用已关闭任务。
- 直接模式不产生机械执行/完成收据，不绕过宿主或用户保留事项，不替项目设定费用、账号、数据、委派或重试政策；撤回、越界、未知消费保真实停止边界。正式审核、接受、发布及其他类别继续走各自门。
- 根upgrade-project新增CompleteOriginalExternalResult只读完成分支。新合格工具读取单操作binding2的原准入、旧固定来源和原义务，保留原来源漂移FAIL及工具原返回；支持任务已关闭、后续policy演进及无关来源许可新增。返回历史事实与当前判断，始终futureExecution=NOT_GRANTED，不修改旧包、不重放调用或恢复旧执行权。
- 新行为并入现有授权、过程、格式与显示入口验证；真实旧固定包兼容另作隔离代表，合成资格和实际分发分别标识。最终资格只取冻结候选的实际必要验证及独立审核，不由本变更记录宣称通过。

## 历史结案、同活动操作与验证复用（源码候选）

- 历史证据按原对象根解释相对引用，并独立应用当前消费保护；严格JSON共用解析核保持对象入口，合法材料数组由值入口读取。原生产与历史成功的完整义务继续验证，不以根修复豁免缺失义务。
- 无候选材料释放立即返回；成功producer只交出已验证的本次保留事实，原IO残留须精确匹配。显式RUNTIME_MAINTENANCE沿原准入和删除核处理当前有限任务负责的旧精确集合，部分失败保留真实remaining，不增加清理平台。
- 同一健康工作活动中的本地配套操作由原checker/ADMIT核当前权限和路线，当前要求无新增且仅操作规则退场时不装配正文；当前完整义务冻结到新compact和原FINALIZE。sourceObservation2只增加原FULL的loadedRuleIds和真实workRoute，旧观察/收据分支保持。实际自测、自查、返修、恢复或新增要求仍完整加载。
- binding2的Owner保持合法主路线，外部动作核有效EXTERNAL阶段及当前明确许可；binding1兼容约束保持。EXAMPLES给出本地单输入构造例子，真实评估全部escalationFlags，按实际字节生成payload，不授予上传、付费或重试权。
- 两类Bootstrap在调用前说明外层与内层输出预算；完整官方text实际截断时从同次结果补完整缺失单元，不重新选择。新有限成果与新独审默认新会话，同成果/同审有界修复可健康续作；成果交付、原结果消费且无后续职责时由实际收尾者归档会话并核对。
- runner在真实复用路径懒建单次私有原件解析索引，逐次仍核全部成员身份与原validator；无resume和必需fresh短路不建索引。独立返回、漂移拒绝及退出释放保持，不缓存PASS。必要完整资格由当前D3与实际suite/proof核对，旧三组特例不延伸到本批。
- 以上为开发候选能力，源码资格、独审接受、实际新包和项目显式采用分别取证；不从局部测试或静态解析次数推断自然任务、宿主费用或总性能收益。

## 项目质量阶段与必要步骤减负（源码候选）

- policy3 可显式选择质量阶段，稳定适用规则补充所需阶段；一次准备产生 plan2/qualityBinding1，完整成果、当前与历史、审核、接受、关闭及证据消费者使用同一选择。未启用保持 LEGACY，显式零选择如实表示未经这些质量阶段验证，权限、真实失败、独立性和专门通道保持。
- 仅在已证明当前 ADMIT 内部执行完整独立 checker 的普通仓库与 Maintenance 分支，移除外层重复调用；未证明的分支保留原检查。严格无包、无副作用、当前用户响应的 NONE 可不单独机械 FINALIZE，显式收口与真实副作用仍受原门约束。
- 无自查阶段的交审仍绑定实际成功生产结果，自动生产、测试与交审续链消费原结果；测试失败不因项目策略变成成功。严格格式、历史原件、完整审核范围及贡献者排除继续核对。
- 当前只具备定向自查候选，整版源码验证、独立 Source Review、接受、新固定分发与项目显式采用尚待完成；不由步骤减少推断实际宿主费用或整任务提速。
