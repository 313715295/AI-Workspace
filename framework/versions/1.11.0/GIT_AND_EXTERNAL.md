# Git and external actions

Git evidence is repository-specific. Use the versioned protected safe-Git helper, exact safe.directory configuration and explicit Git top. Never combine Maintenance, Framework target or consumer state into one status claim.

`GIT_STAGE`, `GIT_COMMIT`, `PUSH` and `EXTERNAL` are separate actions. Use exact paths; never substitute `git add .`. A source or Review package grants none of them.

Before staging, reprove candidate identities, index state, unrelated dirty paths and Review disposition. After commit, report commit and parent identities plus protected-safe status/index. Push requires remote and branch authority and fresh remote evidence.

A Framework release and a project's explicit upgrade are independent. Framework Git publication does not discover or modify consumers.

No background publication, retry/compensation, account action or external claim is implied by local PASS.
