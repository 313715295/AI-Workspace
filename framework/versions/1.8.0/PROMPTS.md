# Prompt patterns

## Cold recovery

Prove cwd and Git top, then read repo-local project/controller/Bootstrap and resolve only the project pin. Load the manifest-selected modules and current project facts. Recovery is read-only; report owner, task, boundaries, evidence ceiling and unique next action.

## Implementation launch

Given a valid signed package, bind task, owner, actor, Controller epoch, actions, exact paths/identities, repository/config and user decision. Materialize the strict ephemeral `LAUNCH` input and invoke `<FW>/scripts/resolve-workflow-route.ps1`; begin the granted actions without a second START only on `IMPLEMENTATION_READY`. Otherwise return the narrow drift.

## Task routing

Evaluate project, cwd/Git top, outcome, owner role, lineage, resource route, protection, Git/device/external boundary and current public decision. Materialize the strict ephemeral `ROUTE` input and invoke `<FW>/scripts/resolve-workflow-route.ps1`; return exactly `REUSE`, `MUST_NEW` or `BLOCKED`. Same-scope user-approved work may create the required visible task; boundary or public-decision changes return `BLOCKED`.

For terminal delivery, authenticated task messages, Controller handoff and hot-state projection, invoke the matching `TERMINAL`, `MESSAGE`, `HANDOFF` or `HOT_STATE` operation before claiming the transition. Missing mandatory input fails closed. Remove the ephemeral input after use; neither it nor the resolver result is authority or a ledger.

## Review

Consume a pure Review package, independently verify the frozen candidate and return findings, evidence ceiling and Git disposition. Do not write or repair.

## Framework maintenance

Start from the Maintenance control repository. Modify only a new final-version candidate and authorized root integration paths. Never edit stable releases, discover consumers or change project pins. Candidate Review, release seal, Git and push are separate gates.
