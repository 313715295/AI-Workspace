# Codex 宿主适配 v1.3.2

本文件只描述 Codex 当前任务、独立任务会话、内部子 Agent 和消息工具的适配方式。项目治理的永久规则仍由`GOVERNANCE.md`、`WORKFLOW_PLAYBOOK.md`与`REVIEW_CHECKLIST.md`持有；其他宿主不继承本文件中的工具名或界面约定。

## 1. 载体映射

- 当前任务：用户正在直接交互的owner上下文。
- 内部子Agent：只用于owner当前turn必须消费、可独立并行且预计一次有界汇合即可完成的子问题。
- 独立任务会话：用于跨turn、预计返工、需要独立审计记录或需要在后台继续的任务。
- 任务、thread、chat和conversation在Codex界面中均视为同一类会话对象；用户侧统一称“任务”。

载体选择不改变唯一owner、文件范围、审核独立性、Git或外部权限。内部子Agent不能冒充独立任务会话，提示词角色切换也不能冒充独立审核。

## 2. 主动回传与等待

独立任务会话默认依靠主动消息回传，owner、执行者和审核者不调用`wait_threads`或等价轮询维持进度感。

只有三类例外允许对同一触发事件和同一目标做一次有界等待或即时快照：

1. 用户明确要求同步等待；
2. 当前turn必须消费结果，且预计一次有界等待可以完成；
3. 目标已经主动回传，但有具体证据怀疑消息丢失。

超时或没有实质变化后不得立即重试，直到出现外部状态变化或用户新指令。为ACK、普通进度、idle或“看看是否完成”而等待属于执行偏差。

## 3. 执行与审核消息

- 执行者稳定候选后，只向任务约定的接收者发送一次完整交接；侧栏完成、任务final或进入idle不能替代回传。
- 固定对象成功发出后执行者立即停写，不以接收ACK作为停写条件。
- 审核者第一条实质结论自动兼作ACK。只有对象身份、范围、独立性、权限不匹配，或无法立即开始且必须保留异步交接时，才发送一次条件式ACK或阻断说明。
- 范围内返工可以按任务预授权直返执行者；范围、产品、跨域owner、权限、质量底线、同一发现复发或轮次上限立即回唯一owner。
- 最终`APPROVED / BLOCKED`直接回唯一owner；审核者不因此取得写入、Git、阶段或外部动作权。

## 4. actor与notifier扩展

`current_actor`、`next_actor`、`review_start_notifier`和直接审核闭环字段是Codex多会话任务的可选宿主扩展，不是核心任务合同。只有实际挂载多个独立任务会话且这些字段能减少歧义时才启用。

- owner自己冻结、委派或续审时，`review_start_notifier=NONE`，不得制造owner通知自己的阶段消息。
- 普通执行者发起Review时可使用`EXECUTOR`；审核者没有必要重复发送Review开始通知。
- 未启用多会话适配时，任务卡不得为了通过模板而填充虚构actor/notifier。

1.3.2 checker在这些扩展字段存在时验证一致性；字段不存在时只验证核心范围、生命周期和机器观察actual。
